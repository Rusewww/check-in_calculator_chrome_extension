# Check-in Calculator (Chrome extension)

Find out exactly when online check-in opens for your flight, in the airport's time zone
and in yours — from the browser toolbar, with no tab to open and nothing sent anywhere.

**[Get it from the Chrome Web Store](https://chromewebstore.google.com/detail/check-in-calculator/oifiigbmkgoojkfdjbkpknkgemgcgeog)**

Website (the same calculator, as a page): https://rusewww.github.io/check-in_calculator/

## What it does

1. Click the toolbar icon. Pick the departure airport by IATA code (or airport / city
   name).
2. Enter the scheduled departure date and time, as printed on your ticket (local time
   at the airport).
3. Choose how long before departure check-in opens: **Hours** (12, 24, 36, 48, 72) or
   **Days** (3, 5, 7, 10, 30, 60), or type a custom number.
4. Optionally pick the time zone to show times in (defaults to the airport's zone).

You get the opening time in the airport's zone and in yours, the UTC offset of each, the
time-zone difference at that moment, a live countdown or "check-in is open" status, and
buttons to **add the opening time to Google Calendar**, **download an .ics file** for
Apple Calendar, Outlook and others, or **copy a link** back to the website carrying the
same inputs.

The popup reopens on your last airport, departure, window and zone, so most return
visits need at most one changed field. The top bar has an Auto / Light / Dark theme
switch and a language button (English by default, Ukrainian and German).

Daylight-saving changes are handled: "N hours before" is exact elapsed time, "N days
before" is the same local time N calendar days earlier at the airport, and a departure
time that does not exist or exists twice on a change-over night is flagged.

Everything is computed from the browser's own built-in IANA time-zone database. There is
no server, no account, no analytics, and no data leaves the device — see
[docs/privacy-policy.md](docs/privacy-policy.md).

## Install

From the [Chrome Web Store](https://chromewebstore.google.com/detail/check-in-calculator/oifiigbmkgoojkfdjbkpknkgemgcgeog) —
the usual route. To load an unpacked build from source instead (for development, or to
try an unreleased change):

```bash
npm install
npm run build
```

Then in Chrome: `chrome://extensions` → enable **Developer mode** → **Load unpacked** →
select the `dist/` folder.

## Development

Requires Node.js 22 or newer.

```bash
npm install
npm run dev          # popup served at http://localhost:5173/popup.html for fast iteration
npm test             # unit tests (Vitest)
npm run lint         # ESLint
npm run typecheck    # JSDoc types checked with tsc
npm run format       # Prettier
npm run build        # production build into dist/ (load this folder as an unpacked extension)
npm run data:build   # regenerate public/data/airports.json from open data
npm run build:icons  # regenerate public/icons/*.png and store-assets/store-icon-128.png
npm run build:fonts  # regenerate public/fonts/*.woff2 (Geist + Geist Mono, Cyrillic subset)
npm run package:zip  # dist/ -> check-in-calculator-<version>.zip, enforcing the size budget
npm run check        # everything CI runs, including the zip
```

`npm run dev` serves the popup in a plain browser tab (no `chrome.*` APIs), which is
enough to iterate on layout and logic; preferences just aren't persisted in that mode.
Test the real popup — including the native date/time pickers, storage persistence and
the toolbar icon — via **Load unpacked** as above.

Layout:

```
src/core/        pure logic (time zones, period rules, calculation, search, URL state, calendar)
src/data/        loads the bundled airport dataset; chrome.storage.local port
src/ui/          DOM components, state, strings, styles (shared with the website)
src/extension/   popup entry point, popup-only layout CSS
scripts/         data pipeline, icon/font generation, zip packaging
public/          copied verbatim into dist/: dataset, fonts, icons
assets/brand/    source SVGs for the generated icons (not shipped)
tests/           Vitest suites, including checks on the shipped dataset
docs/            architecture record and the privacy policy source text
```

See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) for the design this extension inherits
from the website (the website keeps its own repository), the data sources and the
reasoning behind the technical choices.

## Airport data

`public/data/airports.json` is generated by `scripts/build-airports.mjs` from:

- [OurAirports](https://ourairports.com/data/) (public domain): codes, names, region,
  country, type, scheduled-service flag, coordinates.
- [mwgg/Airports](https://github.com/mwgg/Airports) (MIT): IANA time zone per airport.
- [geo-tz](https://github.com/evansiroky/node-geo-tz) (MIT, build time only): time zone
  from coordinates for airports missing above.

The dataset is validated by the test suite (unique codes, valid zones, known airports).

## Permissions

Only `storage` — to remember the chosen theme, language, display time zone and the last
flight entered, so the popup opens on the previous answer. No host permissions, no
`tabs`, `activeTab`, `scripting`, `downloads`, `identity` or `cookies`. The extension
cannot read or modify the pages you visit.
